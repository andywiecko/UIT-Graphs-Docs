    Key

    Position

    The user can use one of 21 predefined key positions to place the key automatically. Below you can find a schematic figure showing the corresponding key positions for the USS --graph-key-position property values. The graph canvas border is marked with a solid black line. Alternatively, you can configure this in C# using the KeyPosition enum (with the same names in CamelCase).

    • USS
    • C# 
    .graph-canvas {
    --graph-key-position: in-top-right;
}

    var graph = new Graph
{ 
    Theme = { Key = { Position = KeyPosition.InTopRight } } 
};

    Visibility

    By default, key visibility is set automatically. If a Graph contains plots with a non-null and non-empty title, the key will be rendered. Otherwise, it is hidden by default. Below you can find a table with possible key visibility settings, which can be configured via the USS --graph-key-visibility property or via C# using Graph.Theme.Key.Visibility.

    USS C# Description
    auto KeyVisibility.Auto The key is visible only if it contains visible attached elements.
    always KeyVisibility.Always The key is always visible, even if no elements are attached.
    never KeyVisibility.Never The key is never visible, even if it contains elements.
    manual KeyVisibility.Manual Key visibility is controlled manually using key.style.display.
    • USS
    • C# 
    .graph-canvas {
    --graph-key-visibility: auto;
}

    var graph = new Graph
{ 
    Theme = { Key = { Visibility = KeyVisibility.Auto } } 
};

    Styling

    Currently, all key styling can be achieved using built-in UI Toolkit properties. Check out the USS classes and default configuration:

    .graph-key {
    flex-direction: column;
    align-items: flex-end;
    border-width: 1px;
    margin: 6px;
}

.graph-key-element {
    flex-direction: row;
    margin: 1px;
    font-size: 12px;
}

.graph-key-style-preview {
    width: 40px;
    margin: 2px;
}

    Alternatively, you can configure this through C#. Just use the Key reference:

    var graph = new Graph
{
    Key = { style = { ... } }
};

    Keep in mind that depending on the KeyPosition, the object can be parented to different elements. Because of this, it is recommended to use graph.Key instead of querying it manually using graph.Q<Key>(). See the UXML reference for details regarding the Key element structure.
